## ⚙️ Step 1 — Install Emscripten (EMSDK)

> Do this ONCE on your Windows machine.

### 1.1 — Install Prerequisites

Make sure you have:
- **Git** → https://git-scm.com/download/win
- **Python 3** → https://www.python.org/downloads/ *(check "Add to PATH")*
- **CMake** → https://cmake.org/download/
- **Visual Studio Build Tools** → https://visualstudio.microsoft.com/visual-cpp-build-tools/
  *(Choose "Desktop development with C++")*

### 1.2 — Download and Install EMSDK

Open **Command Prompt** (or VS Code Terminal) and run:

```bash
# 1. Clone the emsdk repo into your home folder
cd %USERPROFILE%
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk

# 2. Download and install the latest Emscripten
emsdk install latest

# 3. Activate it
emsdk activate latest

# 4. Set up environment variables for this session
emsdk_env.bat
```

### 1.3 — Verify Installation

```bash
emcc --version
```

You should see something like: `emcc (Emscripten gcc/clang-like replacement + linker) 3.x.x`

## 🔨 Step 2 — Compile the C Game to WebAssembly

### Option A: One-Click (Recommended)

In VS Code Terminal, run:

```bash
run.bat
```

This automatically:
1. Activates Emscripten
2. Compiles `maze.c` → `maze.js` + `maze.wasm`
3. Starts a local HTTP server on port 8080
4. Opens your browser at `http://localhost:8080`

### Option B: Manual Command

```bash
call %USERPROFILE%\emsdk\emsdk_env.bat

emcc maze.c -o maze.js ^
  -s WASM=1 ^
  -s EXPORTED_FUNCTIONS="['_js_startGame','_js_movePlayer','_js_checkWin','_js_getMoves','_js_getElapsed','_js_getRows','_js_getCols','_js_getMazeCell','_js_isGameWon']" ^
  -s EXPORTED_RUNTIME_METHODS="['cwrap']" ^
  -s ALLOW_MEMORY_GROWTH=1 ^
  -s MODULARIZE=0 ^
  -s ENVIRONMENT=web ^
  -O2
```

### Option C: VS Code Task

Press `Ctrl + Shift + B` to run the default build task.

### Option D: Start Python Server Manually

```bash
python -m http.server 8080
```
Then open: `http://localhost:8080`

## 🧠 Emscripten Compilation Flags — Explained

| Flag | Meaning |
|------|---------|
| `emcc maze.c` | Compile maze.c using Emscripten compiler |
| `-o maze.js` | Output: generates maze.js (glue) + maze.wasm (binary) |
| `-s WASM=1` | Enable WebAssembly output (not just asm.js) |
| `EXPORTED_FUNCTIONS` | Tell Emscripten which C functions to expose to JavaScript |
| `EXPORTED_RUNTIME_METHODS=['cwrap']` | Export cwrap so JS can call C functions easily |
| `ALLOW_MEMORY_GROWTH=1` | Allow WASM memory to grow dynamically |
| `MODULARIZE=0` | Don't wrap in a module; use global `Module` object |
| `ENVIRONMENT=web` | Target the browser environment |
| `-O2` | Optimization level 2 (faster + smaller output) |

## 🔬 How WebAssembly Works — Simple Explanation

```
  ┌──────────────┐      emcc       ┌─────────────────────────────┐
  │   maze.c     │  ──────────►   │  maze.wasm (binary bytecode) │
  │  (C source)  │                │  maze.js   (JS glue code)    │
  └──────────────┘                └─────────────────────────────┘
                                              │
                                              ▼
                                  ┌──────────────────────┐
                                  │   Browser / V8 Engine │
                                  │                       │
                                  │  1. Downloads .wasm   │
                                  │  2. Compiles to native │
                                  │     machine code       │
                                  │  3. Runs at near-      │
                                  │     native speed!      │
                                  └──────────────────────┘
```

### Think of it like this:

| Analogy | Tech Equivalent |
|---------|----------------|
| You write a letter in English | You write code in C |
| The letter is translated to a universal code | Emscripten compiles to .wasm |
| Anyone with a decoder can read it | Any modern browser can run it |
| The decoder makes it readable | The browser JIT-compiles .wasm → machine code |

### Key Facts about WebAssembly:
1. **Not JavaScript** — it's a separate binary format (like a .exe but for browsers)
2. **Runs in a sandbox** — safe, can't access the OS directly
3. **Near-native speed** — 80-95% as fast as native C
4. **Works everywhere** — Chrome, Firefox, Safari, Edge all support it
5. **JavaScript bridge** — JS calls WASM functions and reads results

## 🎯 Maze Generation Algorithm — How it Works

The maze is generated using **Recursive Backtracking (DFS)**:

```
1. Fill entire grid with walls (#)
2. Start at cell (1,1) — mark it as path
3. Pick a random unvisited neighbour (2 steps away)
4. Carve a path through the wall between them
5. Recursively repeat from the new cell
6. When stuck, backtrack to last cell with unvisited neighbours
7. Place Player (P) at (1,1) and Exit (E) at (rows-2, cols-2)
```

This always generates a **perfect maze** — exactly one solution path, no loops.

## 🏆 Viva Questions & Answers

### Q1: What is WebAssembly?
**A:** WebAssembly (WASM) is a low-level binary instruction format that runs in web browsers at near-native speed. It allows code written in languages like C, C++, and Rust to be compiled and executed in the browser safely.

### Q2: What is Emscripten?
**A:** Emscripten is a compiler toolchain that converts C/C++ code to WebAssembly. It uses LLVM under the hood and also generates JavaScript "glue code" that lets browsers load and interact with the WASM binary.

### Q3: How does JavaScript call C functions?
**A:** Using `Module.cwrap()` — a utility provided by Emscripten. Example:
```js
const wasmMove = Module.cwrap("js_movePlayer", "number", ["number"]);
wasmMove(0); // Call C's js_movePlayer(0) from JavaScript
```

### Q4: What is `EMSCRIPTEN_KEEPALIVE`?
**A:** It's a macro that marks C functions to be included in the WASM export even if the C compiler thinks they're unused. Without it, the optimizer would remove them.

### Q5: What is structured programming?
**A:** A programming paradigm that uses three control structures: sequence, selection (if/else), and repetition (loops). It avoids `goto` and organises code into functions. Our maze.c uses this with clearly defined functions for each task.

### Q6: How does the maze generation work?
**A:** Using Recursive DFS (Depth-First Search) backtracking. The algorithm starts from one corner, randomly carves paths to unvisited cells, and backtracks when stuck — guaranteeing a solvable maze with exactly one solution.

### Q7: Why can't you open index.html directly?
**A:** Browsers block `.wasm` files when loaded from the local file system (`file://`) due to security (CORS policy). A local HTTP server (`python -m http.server`) serves files over `http://localhost` which browsers allow.

### Q8: What does `-O2` mean in the compile command?
**A:** It's an optimisation level. `-O2` tells the compiler to apply moderately aggressive optimisations — making the WASM output faster and smaller, without breaking the code.

### Q9: What is the difference between maze.js and maze.wasm?
**A:** `maze.wasm` is the compiled binary containing all the C game logic. `maze.js` is auto-generated JavaScript glue code that loads the `.wasm` file, sets up memory, and exposes the `Module` object to your code.

### Q10: How is the timer implemented?
**A:** In the C code, `emscripten_get_now()` records the start time in milliseconds when the game begins. Elapsed time = current time − start time. On the JS side, `setInterval` calls `wasmGetElapsed()` every 100ms to update the display.

## 🛠️ Troubleshooting

| Problem | Solution |
|---------|----------|
| `emcc: command not found` | Run `emsdk_env.bat` first, or update `EMSDK_PATH` in run.bat |
| `maze.wasm` not loading | Must use `http://localhost` not `file://`. Run the local server. |
| Blank screen / console errors | Open DevTools (F12) and check the Console tab |
| Game feels slow on Hard | Normal — 21×21 DFS generation is fast, rendering scales with screen |
| Port 8080 in use | Change `8080` to `8081` in run.bat and tasks.json |
